## Broader vision: LLM-driveable instrumentation for all voice hooks

### Context
Manual testing of voice/LiveKit changes currently needs a second human in the
call, which is slow and unreliable. The voice E2E harness (added alongside this
issue) solves the *Room-level* case: it exposes `window.__lkRoom` +
`__lkCaptureDiagnostics` / `__lkForceResubscribeMic` / `__lkGetInboundAudio` /
`__lkGetLocalMicDeviceId` (dev/`VITE_LIVEKIT_TEST_HOOK` only) and drives 2–3 real
browsers from Playwright to assert "can A hear B" via getStats.

That covers the *Room* surface. It does **not** yet let an LLM exhaustively drive
and assert the behaviour of the individual voice **hooks**.

### The ask
A generic, dev-only instrumentation surface so an LLM (or any automated test) can
exercise every voice hook in isolation and observe its outputs — without a human
and without wiring a bespoke harness per hook. Candidate hooks:

- `useTrackSubscription` (subscribe/unsubscribe/force-resubscribe, policy application)
- `useSpeakingDetection` (VAD gate open/close, thresholds, hysteresis)
- `useDeviceSettings` / `useDeviceTest` (enumerate, switch, permission states)
- `useLocalMediaState` / `useParticipantTracks` (derived media state)
- `useDeafenEffect` / `useRemoteVolumeEffect` (volume/deafen application)
- `useVoiceRecovery` (post-refresh rejoin window)

### Proposed approach (to evaluate)
1. A dev-only `window.__voiceHooks` debug surface that publishes each hook's
   current state + a few imperative actions, populated from a single mount point
   (similar to the existing `VoiceTestHooks`). Gated by
   `import.meta.env.DEV || VITE_LIVEKIT_TEST_HOOK`, tree-shaken in prod.
2. A dedicated Playwright "hook harness" route/page that mounts hooks against a
   fake or real `Room` so each can be driven and asserted in isolation
   (complements the full-app voice specs).
3. Reuse the existing fake-LiveKit-Room test scaffolding from
   `src/__tests__/integration/voiceLifecycle.test.tsx` as the unit-level
   counterpart.

### Why later, not now
Tangential to the two voice PRs that motivated the harness; the Room-level hooks
already unblock the immediate "validate fixes without a second human" need.
Filing so it isn't lost.
